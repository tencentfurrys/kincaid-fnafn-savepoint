OBJECTIVE

    every device. Find and fix the fault inside 2.7.8.

CRITICAL CONSTRAINT (user-confirmed)

--------------------------------------------------------------------------------
0. TL;DR — ROOT CAUSE (disassembly-level, verified)
--------------------------------------------------------------------------------
2.7.8's ARM runtime added an input-stealing gate inside HandleMouse():

    if (GraphicsPerf::IsMouseOverDebugOverlay()) -> SKIP ALL mouse/touch handling

IsMouseOverDebugOverlay() returns ImGui::GetIO()->WantCaptureMouse when a
debug-overlay global is set and a GraphicsPerf input-capture flag (bit6) is on.
When it returns true, 2.7.8 discards every touch BEFORE any game logic sees it:
game renders fine, touches do nothing. Per-device because the overlay/hover
geometry and the game's own show_debug_overlay() usage vary by device.

2.6.1 HAS NO SUCH GATE — its HandleMouse goes straight to HandleGestures().

FIX: patch IsMouseOverDebugOverlay() to "return 0" in both ARM libs
(arm64-v8a + armeabi-v7a) of 2.7.8. 8 bytes each. Not yet applied (see §6).

6. THE FIX — EXACT PATCH SPEC (next session: implement + verify)
--------------------------------------------------------------------------------
  Target: GraphicsPerf::IsMouseOverDebugOverlay() in BOTH ARM libs of 2.7.8.
  Make it return 0 unconditionally. This kills the HandleMouse gate and the
  GML wrapper in one shot, changes nothing else, adds no relocations.

  arm64-v8a (kincaid/lib/arm64-v8a/libyoyo.so):
    function vaddr 0x66b848. Write at function entry:
      mov w0, wzr   = word 0x2A1F03E0  -> bytes E0 03 1F 2A
      ret           = word 0xD65F03C0  -> bytes C0 03 5F D6
    (both words already exist verbatim inside this same function at
     0x66b868/0x66b86c region — safest possible patch)

  armeabi-v7a (kincaid/lib/armeabi-v7a/libyoyo.so):
    function vaddr 0x4a735c. Write at function entry:
      mov r0, #0    = word 0xE3A00000  -> bytes 00 00 A0 E3
      bx  lr        = word 0xE12FFF1E  -> bytes 1E FF 2F E1
    (again both already present in the same function)

  Procedure:
    1. Map vaddr -> FILE OFFSET via ELF program headers (PT_LOAD,
       p_offset + (vaddr - p_vaddr)). Do NOT assume offset==vaddr. Verify
       by disassembling the 8 bytes at the computed file offset and
       confirming they match the known prologue (arm64: d0003508 adrp... /
       v7a: e59f0044 ldr r0,[pc,#0x44]...).
    2. Pre-flight: scan .rela.dyn/.rel.dyn (and .rel.dyn on v7a) for any
       relocation with r_offset inside [funcaddr, funcaddr+8). Expect none;
       abort if found and reconsider.
    3. Overwrite the 8 bytes in each extracted .so; sha256 before/after;
       disassemble the patched function to confirm
       `mov w0,wzr ; ret` (resp. `mov r0,#0 ; bx lr`).
    4. Surgical zip-rebuild (see out/kincaid-278-logger-surgical method):
       copy every entry byte-identical from the ORIGINAL 2.7.8 APK, replace
       ONLY lib/arm64-v8a/libyoyo.so and lib/armeabi-v7a/libyoyo.so, drop
       META-INF sigs, zipalign -f -p 4, apksigner sign with opencode-debug.jks.
    5. Name: kincaid-v2025.9-INPUTFIX.apk -> Downloads. Include a short
       README: uninstall original first (cert), saves lost, x86/cloud
       unaffected, only debug-overlay input interception is disabled.

  Optional (only if wanted): also neuter F_IsKeyboardUsedDebugOverlay's
  helper the same way. It has no input-path callers on arm64, so it is NOT
  needed for the touch fix.

  RISK / HONESTY:
    * The gate's EXISTENCE and its ABSENCE in 2.6.1 are disassembly FACTS.
    * That this gate is THE cause of the user's per-device dead touch is a
      STRONG HYPOTHESIS (only input-killing difference found; per-device by
      construction; game data calls show_debug_overlay only in 2.7.8) —
      NOT yet proven on failing hardware, which is unavailable.
    * If the patch does not fix a device: use the LOGGER apk on that device
      and follow README-LOGGER.txt's decision tree (activity-layer touches
      present? view-layer present? window_focus?). Next suspects in order:
        a) SYSTEM_ALERT_WINDOW overlay windows (2.7.8-only permission)
        b) ImGui window geometry on odd displays (foldables, notches)
        c) refresh-rate path (mCurrentRefreshRate/mGameSpeedControl)
    * The patch cannot break normal play: worst case a hidden debug overlay
      no longer intercepts touches — which is the desired outcome anyway.
